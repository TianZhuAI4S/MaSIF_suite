# Step 13 — Ligand-preserving Rosetta refinement

## Purpose

Run the scientific workflow beyond neural-network inference: create a Rosetta-readable ligand, assemble a target–binder complex, run the original neosurface relaxation and interface-design protocols, and inspect real output structures and scores.

## Intended behavior

- Keep the small molecule throughout parameterization, relaxation and design.
- Reuse the upstream XML unchanged and record SHA-256 hashes.
- Execute external programs from a task-owned object with explicit binary, database and Python paths.
- Keep target and ligand in chain A and the binder in chain B, as required by the original interface selectors.
- Check process exit status, finite score metrics, finite coordinates and retained partner/ligand records.
- Optionally repeat interface design with the same Rosetta RNG seed and compare coordinates and score values exactly.

## Protocol and input provenance

Inputs are the real `example/1a7x.pdb` and `example/1a7x_C_FKA.sdf` from the pinned neosurface repository. The target is protein chain A, the binder is protein chain B, and the molecule is FKA from chain B. The Rosetta adapter renames the target/ligand chain to A and the binder chain to B. It retains protein coordinates and uses atom names generated by Rosetta's original `molfile_to_params.py` for the molecule.

The protocol files are copied byte for byte from `rosetta_scripts/seed_refine/src/`:

- `relax.xml`: the original FastRelax protocol, repeats = 1.
- `interface_design.xml`: the original protocol with two FastDesign mover applications and pre/post interface metrics.
- `no_ref.rosettacon2018.beta_nov16.txt`: the original design schedule.

`nstruct=1`, `constant_seed`, and `jran=42` control the demonstrated run. The repeat check starts from the same relaxed structure.

## Protonation issue localized before execution

The raw FKA record has 67 heavy atoms and only four explicit hydrogen atoms. Merely testing whether at least one hydrogen exists misses this incomplete protonation. The adapter assigns bond orders from the supplied connectivity template and calls `Chem.AddHs(addCoords=True)` to complete implicit valences. The prepared ligand has 143 atoms, including the unchanged 67 heavy atoms.

The implementation asserts that every pre-existing atom retains exactly the same coordinates during hydrogen completion. New hydrogen placement uses the installed RDKit version; it is a preparation repair, and is **not** evidence that historical RDKit/Reduce pipelines produce identical hydrogen coordinates.

The original ligand-contact selection is executed without changing its radii or side-chain rules. For the completed ligand, its pre-relaxation selection is `82A`. The task supports an empty selection exactly as returned by the source, without inventing a fallback contact.

## Scope

This adapter currently accepts one protein chain per partner. This task executes relaxation and interface design. Scaffold grafting and a complete scaffold-database search are separate upstream Rosetta workflows; this task does not label a refinement run as grafting success. Rosetta's determinism check uses the same binary, database, input and seed; it does not establish equality across Rosetta versions or machines.
